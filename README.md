# ЛР4 — ИИ для обнаружения DDoS-атак (PostgreSQL + Python)

Продолжение ЛР3. Сохранено всё из ЛР1–ЛР3: схема, ввод данных, ограничения, ссылочная целостность, ALTER TABLE, конструктор SELECT с CASE/COALESCE/NULLIF, подзапросы ANY/ALL/EXISTS, пользовательские типы, поиск LIKE/regex/SIMILAR TO, строковые функции, мастер JOIN, лог. Добавлены ROLLUP / CUBE / GROUPING SETS, представления (VIEW и MATERIALIZED VIEW) и конструктор CTE (WITH).

## Стек
- Python 3.12+ (проверено на 3.15), PySide6, psycopg2
- PostgreSQL 13+ (проверено на 19)
- ОС: Windows / Linux / macOS

## Запуск
```
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python app.py
```
Подключение задаётся в `config.ini`: localhost:5432, БД `ddos_lab4`, postgres/postgres. Если базы нет, она создаётся при подключении. Порядок работы: «Подключиться» → «Создать схему и таблицы» → «Добавить демо-данные».

## Что добавлено в ЛР4
1. **ROLLUP, CUBE, GROUPING SETS** — блок «Расширенная группировка» в конструкторе SELECT (окно «Показать данные»).
   - Режим выбирается в выпадающем списке: обычный GROUP BY, ROLLUP (подитоги по иерархии и общий итог), CUBE (все комбинации и общий итог), GROUPING SETS (свои наборы).
   - Порядок столбцов для ROLLUP задаётся кнопками ▲ и ▼.
   - Наборы GROUPING SETS собираются кнопками: набор из отмеченных столбцов или общий итог `()`.
   - Итоговые строки можно подписать «ИТОГО» через `GROUPING()`. Столбец `grouping_level` показывает уровень детализации, итоговые строки выделены жирным.
   - Кнопка «Пример отчёта» строит отчёт по запускам: статус × GPU.
2. **Представления (VIEW)** — отдельное окно, кнопка «Представления» в главном окне.
   - Видны все представления схемы: вид, число столбцов, структура, сохранённое определение и данные.
   - Новое VIEW создаётся из запроса, собранного в конструкторе SELECT, мастере JOIN или конструкторе CTE, без ручного SQL.
   - Обновить определение можно через CREATE OR REPLACE. Есть переименование и удаление (с CASCADE).
3. **MATERIALIZED VIEW** — в том же окне.
   - Создание WITH DATA или WITH NO DATA, обновление кнопкой «Обновить данные (REFRESH)», просмотр данных.
   - Видно отличие от обычного VIEW: после изменения таблиц обычное VIEW сразу показывает новые данные, а материализованное — старый снимок до REFRESH.
   - Представления можно выбирать как источник в конструкторе SELECT, подзапросах, поиске и мастере JOIN.
4. **Конструктор CTE (WITH)** — вкладка в окне «Показать данные».
   - Запрос собирается из блоков: у каждого блока есть имя, источник, столбцы, агрегаты, WHERE и GROUP BY. Следующий блок может читать предыдущие, например `run_stats` → `best`.
   - Итоговый SELECT берёт данные из блока или таблицы и может соединить их с другим блоком или таблицей (INNER/LEFT/RIGHT/FULL/CROSS JOIN), с выбором столбцов, WHERE, ORDER BY и LIMIT.
   - Кнопка «Пример» строит запрос «лучшие эксперименты» из двух блоков с JOIN.

Все запросы собираются без ручного SQL. Готовый SQL показывается рядом с результатом, ошибки выводятся понятными сообщениями с ROLLBACK. Например: «материализованное представление не заполнено — нажмите REFRESH» или «OR REPLACE не может удалять столбцы представления».

## Структура БД (схема `ddos_ai`)
| Таблица | Назначение | Ключи и ограничения |
|---|---|---|
| `models` | модели ИИ | PK, UNIQUE(name), CHECK, ENUM `model_family`, `tags text[]` |
| `datasets` | датасеты трафика | PK, UNIQUE(name), CHECK, `attack_types attack_type[]` |
| `experiments` | эксперименты | FK → models (RESTRICT / CASCADE), FK → datasets (SET NULL), UNIQUE(title, model_id) |
| `runs` | запуски | FK → experiments (CASCADE), UNIQUE(experiment_id, run_no), CHECK метрик 0..1 |

## Логирование
`app.log`: INFO/ERROR с временными метками — подключения, DDL (включая CREATE/DROP VIEW, REFRESH), DML, SELECT, COMMIT/ROLLBACK, ошибки.
